# Workflow with IBM Bob

## Stage of use
IBM Bob was used in the **review and documentation stage**, after the core project (notebooks, `src/`, SQL, and Streamlit dashboard) had been built.

## Setup
- Installed the IBM Bob IDE and opened the project folder.
- Logged in with a free trial account.
- Used **Ask mode** with **Read-only** auto-approval, so Bob could read the codebase but could not modify any files.
- To conserve trial usage, I kept prompts focused and specific.

## Process
1. **Project analysis:** Asked Bob to read `src/`, `dashboard/`, `sql/`, and `notebooks/`, explain the project end to end, and generate an architecture diagram (Prompt 1).
2. **Diagram refinement:** The first diagram was cluttered, so I asked Bob to simplify it into a clean five-block flow (Prompt 2).
3. **Documentation:** Asked Bob to draft the README from the actual project files, telling it to include only verifiable facts and no invented metrics (Prompt 3).
4. **Review:** Checked each output against the real project and corrected it before using it.

## Outcomes
- `docs/architecture.png`: final architecture diagram generated by Bob.
- Corrected my README folder structure (notebook 03 is `03_sql_analysis`, dashboard pages have numeric prefixes).
- Noticed that `kpi_queries.sql` was a placeholder.
- README: Bob's draft was used as the base and edited by me.

## What I changed after Bob's output
- Rewrote the "How IBM Bob Was Used" section of the README, because Bob's draft overstated its role.
- Adjusted the AI Assistant description to match the actual keyword-based logic.
- Added the architecture image, missing docs entries, and my GitHub details.

## Limitations noticed
- Bob's first diagram chained the dashboard pages together, implying a flow that doesn't exist.
- Bob's README draft described its own involvement more broadly than what actually happened.
- Trial usage limits meant I did not run a full code review with Bob. The `src/` review notes in this project came from my own testing.

## Reflection
Bob was most useful for reading the whole codebase quickly and turning it into documentation and diagrams. Its output still needed human review, which is why responsible AI is a core principle of this project.
